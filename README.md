# AI 방탈출 (AI Escape Room)

AI가 만든 퍼즐을 3D 1인칭으로 풀고 제한 시간 안에 탈출하는 협동 방탈출 게임.
방 안을 돌아다니며 **단서를 직접 찾고**, **미니게임으로 열쇠를 얻어** 문을 여는 모험형 진행입니다.

> **리빌딩 v2** — 두 팀원 프로젝트(「AI 방탈출」 + 「붉은 서재」)를 하나로 합쳤습니다.
> 기반은 「AI 방탈출」(React+TS, FastAPI, 협동, 난이도, 설정, 테스트)이고,
> 「붉은 서재」의 장면·연출·전용 단서 화면을 **세 번째 테마 '붉은 서재'** 로 옮겨 왔습니다.
> 테마: **붉은 서재 · 공포 · 파라오**. 자세한 변경 내용은 아래 「리빌딩에서 바뀐 것」 참고.

### 리빌딩에서 바뀐 것
| 구분 | 내용 |
|---|---|
| 새 테마 | **붉은 서재** (1998년 저택 살인사건): 저택 현관 → 피해자의 서재 → 비밀 서고 → 핏자국의 집무실 → 지하 와인 저장고, 쉬움/보통/어려움 문제 각각 |
| 가져온 장면 | 팀원 모듈을 `frontend/src/game/study/` 로 이식: 셰이더 촛불·벽난로, 크리스털 샹들리에, 비 오는 창문과 번개, 벨벳 커튼, 시신(이미지 투영), 사진 같은 핏자국, 1인칭 손전등 모델 |
| 전용 단서 | `phone`·`diary`·`calendar`·`clock`·`bookshelf`·`portrait`·`body` 오브젝트: 3D 모델(벽시계 바늘·달력 표시·책 제목이 단서 글과 일치) + 전용 조사 화면(휴대폰 잠금화면·일기장·달력·시계·책장·검시 메모). 게임은 멈추지 않음 |
| 공포 연출 | 액자를 2.5초 바라보면 귀신이 튀어나옴, 창밖 번개+천둥, 정전 때 형체+속삭임, 남은 시간 5분/1분 이하 화면 맥동 |
| 화면 품질 | 공포 색보정(채도↓·붉은 그림자·필름 노이즈·비네팅) — 붉은 서재·공포 테마의 중간/높음 품질 |
| 성능 | **자동 해상도**(FPS 48 미만이면 해상도↓), 조명 풀(방이 5개여도 점광원 3개만 옮겨 씀), 책·와인병 InstancedMesh, 작은 소품 그림자 제외, 움직이는 동안 외곽선 쉬기, 빛번짐 절반 해상도, 먼 방 애니메이션 정지 |
| 조작성 | 붉은 서재 오브젝트마다 보이지 않는 조준 상자 → 낮은 탁자 위 쪽지도 쉽게 조사 |
| 이름 | 테마 이름을 **공포 / 파라오** 로 정리 (기존 DB 도 자동 갱신, 관리자가 바꾼 이름은 유지) |

| 영역 | 기술 |
|---|---|
| 프론트엔드 | TypeScript + React 18 (Vite) |
| 3D 엔진 | JavaScript + Three.js (`frontend/src/game/engine.js`) |
| 백엔드 | Python FastAPI + WebSocket |

## 1. 실행 방법

### 한 번에 실행 (Windows · Mac · Linux)
| | 실행 | 종료 |
|---|---|---|
| Windows | **`start.bat`** 더블클릭 | **`stop.bat`** |
| Mac / Linux | 터미널에서 **`./start.sh`** | **`./stop.sh`** |

아래를 자동으로 처리하고 브라우저(http://localhost:5173)까지 엽니다. (`NO_BROWSER=1` 이거나 CI 환경이면 브라우저는 열지 않음)
1. Python 3.10+ / Node.js 설치 확인
2. `backend/.venv` 가상환경 생성, 패키지 설치 (`requirements.txt` 가 바뀌었을 때만 다시 설치)
3. `backend/.env` 가 없으면 `.env.example` 로 생성
4. `frontend` 패키지 설치 (`package-lock.json` 이 바뀌었을 때만 다시 설치)
5. 백엔드(8000)·프론트엔드(5173)를 **창 없이 백그라운드로** 실행 → 응답하면 브라우저 열기

- 서버 출력은 `logs/backend.log`, `logs/frontend.log` 에 저장됩니다. 서버가 켜지다 죽으면(`--reload` 감시 프로세스만 남은 경우 포함) 기다리지 않고 해당 로그의 마지막 부분을 보여 줍니다.
- 끌 때는 **`stop.bat` / `./stop.sh`** 를 실행하세요 (창이 없으므로 창 닫기로는 꺼지지 않습니다). 서버의 하위 프로세스(uvicorn 재시작 감시, npm 아래 vite)까지 함께 종료합니다.
- 이미 켜져 있는 서버는 다시 켜지 않습니다.
- 세 스크립트 모두 GitHub Actions 에서 **실제 Windows / macOS / Linux** 로 실행·응답·종료까지 검사합니다 (아래 CI).

### 백엔드
```bash
cd backend
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```
- 처음 실행하면 `backend/escape_room.db` 가 생성되고 붉은 서재·공포·파라오 테마가 자동 입력됩니다. (이전 DB 에는 붉은 서재가 자동 추가)
- 이전 버전 DB 가 있어도 **자동으로 업그레이드**됩니다 (새 컬럼 추가 + 수정하지 않은 기본 방은 단서/미니게임 포함 내용으로 갱신).
- API 문서: http://localhost:8000/docs
- 테스트: `pip install -r requirements-dev.txt && pytest -q`

### 프론트엔드
```bash
cd frontend
npm install
npm run dev
```
- http://localhost:5173 접속 (`/api`, `/ws` 는 Vite 프록시가 8000번으로 전달)
- 협동 테스트: 브라우저 창 2개를 열어 한 쪽에서 만든 **방 코드 6자리**를 다른 쪽에서 입력

### 환경 변수 (`.env`)
| 파일 | 키 | 설명 |
|---|---|---|
| `backend/.env` | `AI_PROVIDER` | `mock`(현재) / `claude` / `gemini` |
| | `HINT_PENALTY_SEC` | 힌트 1회 감점: 제한 시간 **30분당** 몇 초, 기본 60 (→ 30분 게임 1분, 60분 2분) · 0 이면 감점 없음 |
| | `ADMIN_TOKEN_TTL_SEC` | 관리자 로그인 유지 시간(초), 기본 2시간 |
| | `SESSION_KEEP_HOURS` | 이보다 오래된 게임 세션은 서버 시작 시 삭제, 기본 24 |
| | `AI_API_KEY` | 비워둠. 키를 넣고 `AI_PROVIDER` 를 `claude` / `gemini` 로 변경 |
| | `AI_MODEL` | 비우면 claude → `claude-sonnet-5-5`, gemini → `gemini-2.5-flash` |
| | `AI_RANDOM_ROOMS` | 기본 `true`: 키가 있으면 **게임을 시작할 때마다 AI 가 모든 방의 문제를 새로 생성** · `false` 면 테마의 기본 방 |
| | `AI_DAILY_LIMIT` | 서버 전체 하루 AI 호출 수, 기본 100 (방 생성·힌트·관리자 생성 모두 포함, 0 이하 = 제한 없음) |
| | `AI_GAMES_PER_IP_HOUR` | 같은 IP 가 1시간에 만들 수 있는 AI 게임 수, 기본 5 |
| | `AI_MAX_CONCURRENT_GAMES` | 동시에 AI 로 방을 만드는 게임 수, 기본 2 |
| | `ADMIN_PASSWORD` | 인게임 관리자 비밀번호 — **반드시 변경** (기본값이면 서버 시작 시 경고, 관리자 로그인 시 안내) |
| | `DATABASE_PATH`, `CORS_ORIGINS` | DB 경로, 허용 프론트 주소 |
| `frontend/.env` | `VITE_API_URL`, `VITE_WS_URL` | 비우면 프록시 사용. 배포 시에만 입력 |

> `.env` 는 `.gitignore` 에 포함되어 있습니다. 저장소에는 `.env.example` 만 올리세요.

### 배포 / 시연용 실행 (서버 하나로)
```bash
cd frontend && npm run build        # frontend/dist 생성
cd ../backend && uvicorn app.main:app --host 0.0.0.0 --port 8000
```
`frontend/dist` 가 있으면 백엔드가 게임 화면까지 함께 제공합니다 → 같은 네트워크의 다른 PC에서 `http://<서버 IP>:8000` 으로 접속.
글꼴은 프로젝트에 포함되어 있어 **인터넷이 없어도** 테마 글꼴이 그대로 나옵니다.

### 보안 / 공정성
**관리자 로그인**
- IP 마다 **10분에 5번** 틀리면 잠김. 잠길 때마다 잠금 시간이 **2배** (1분 → 2분 → 4분 … 최대 30분), 하루 동안 조용하면 처음 단계로
- **경계 모드**: 서버 전체 실패가 10분에 30번을 넘으면(여러 IP 로 나눠 시도) 이미 틀린 적 있는 IP 는 한 번만 더 틀려도 잠김. 한 번도 틀리지 않은 관리자 IP 는 그대로 로그인 가능
- 시도를 **먼저 기록한 뒤** 비밀번호를 확인 → 동시에 수십 개 요청을 보내도 한도를 넘지 못함. 틀리면 응답을 0.6초 늦춤
- 비밀번호는 해시 후 상수 시간 비교 (한글 비밀번호도 안전), 길이 256자 제한, 429 응답에 `Retry-After`
- 잠금·로그인 성공은 관리자 패널 **편집 로그**에 `security` 로 기록 (서버 로그에도 경고)
- 로그인 토큰 2시간 만료, 동시에 최대 20개 (넘으면 오래된 것부터 만료), 관리자 응답은 `Cache-Control: no-store`
- 관리자 비밀번호는 코드에 기본값이 없습니다. `backend/.env` 의 `ADMIN_PASSWORD` 를 비워 두면 관리자 로그인이 꺼지고(503), 운영 환경에서는 서버가 시작되지 않습니다
- `APP_ENV=production` 에서 기본값이거나 **약한 비밀번호**(12자 미만 또는 문자 종류 1가지)면 서버가 시작을 거부 (개발 환경은 경고만). 운영에서는 API 문서(`/docs`)도 숨김
- nginx 등 프록시 뒤에서 실행하면 `TRUST_PROXY=true` (프록시가 붙인 `X-Forwarded-For` 의 마지막 값을 접속 IP 로 사용)

**게임 API**
- 정답 제출: 같은 방에서 30초에 6번까지 (동시 요청으로도 넘을 수 없음)
- 방 코드 대입 방지: 없는 방 코드를 1분에 20번 조회하면 REST·WebSocket 모두 잠시 차단
- 과도한 요청 제한: 게임 만들기 IP 당 10분 20개, 힌트 방당 1분 12번, 미니게임 시작 방당 1분 20번, 보관하는 미니게임 문제 최대 5000개
- 같은 방에 같은 닉네임이 들어오면 서버가 `이름 (2)` 처럼 번호를 붙입니다
- 여러 명이 동시에 정답을 내도 방 클리어·다음 방 열기·탈출 처리는 **한 번만** 실행됩니다 (DB 조건부 갱신)
- 새 테마의 방 5개는 AI 에 동시에 요청하고, 테마와 방을 **한 트랜잭션**으로 저장합니다

**WebSocket**
- 다른 사이트에서 연 접속(Origin 이 이 서버나 `CORS_ORIGINS` 가 아님)은 거부
- 방마다 최대 8명, IP 마다 최대 12개 접속, 메시지 4KB 제한, 형식이 틀린 메시지는 무시(연결 유지), 이동·채팅·핑·마크 빈도 제한

**화면 / 응답 헤더**
- 모든 응답: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Permissions-Policy`
- 서버가 제공하는 게임 화면(HTML): `Content-Security-Policy` (외부 스크립트·다른 사이트 안에 넣기 금지)
- CORS: 쿠키 인증을 쓰지 않으므로 credentials 비허용, 필요한 메서드·헤더만 허용

## 2. 모험형 진행 방식

각 방은 아래 요소의 조합으로 구성됩니다.

| 요소 | 3D 표시 | 하는 일 |
|---|---|---|
| 🔎 **단서** | 방 곳곳의 메모·화이트보드·석상·항아리 등 (✨ 반짝이 = 아직 조사 안 함) | E로 조사 → 팀 인벤토리에 공유. **퍼즐 정보는 단서에 나뉘어 있어** 직접 찾아야 풀 수 있음 |
| 🔐 **암호** | 단말기(공포) / 제단(이집트) | 단서를 조합해 정답 입력 |
| 🎮 **미니게임** | 금고·배전반(공포) / 황금 상자(이집트) | 통과하면 🔑 **열쇠** 획득 |
| 🚪 **문** | 방 사이 문 / 최종 탈출문 | E로 조건 체크리스트 확인, 🔑 열쇠 사용 |

**방 클리어 조건** = (암호가 있으면 정답) **AND** (미니게임이 있으면 문에 열쇠 사용)

### 미니게임 3종 (서버가 문제를 만들고 결과를 검증)
| type | 이름 | 방법 | 난이도(1~5)에 따라 |
|---|---|---|---|
| `sequence` | 기억력 | 불빛(문양)이 켜지는 순서를 기억해 그대로 누르기 | 순서 길이, 표시 속도 |
| `wires` | 전선 연결 | 제한 시간 안에 같은 색 단자끼리 연결 | 전선 개수, 제한 시간 |
| `timing` | 타이밍 | 왕복하는 바늘이 초록 구간에 있을 때 멈추기 (3라운드) | 구간 폭, 속도, 필요 성공 수 |

실패하면 몇 번이든 다시 도전할 수 있고, 매번 새 문제가 나옵니다.

### 기본 콘텐츠 구성
| 순서 | 붉은 서재 | 구성 (보통 정답) |

| 1 | 저택 현관 | 쪽지·촛대 메모·초상화 + 그림 수식 자물쇠 (4324) |

| 4 | 핏자국의 집무실 | 시신·벽시계·궤짝·통화 기록 + 금고 (2347) + 🎮괘종시계(타이밍) |
| 5 | 지하 와인 저장고 | 깨진 병·라벨·벽 글씨 + 출구 철문 (1974) + 🎮전선 연결 |

| 2 | 해킹당한 관리자실 | 단서 3 + 암호 + 🎮전선 연결 | 스핑크스의 수수께끼실 | 단서 3 + 암호 |

| 5 | 최종 탈출 통제실 | 단서 3 + 암호 + 🎮타이밍 | 아누비스의 지하 통로 | 단서 3 + 암호 + 🎮기억력 |

### 난이도 (쉬움 · 보통 · 어려움)
로비에서 고르며, 고른 난이도는 다음 방문 때도 기억합니다. **난이도마다 문제 자체가 다릅니다.**

| | 쉬움 | 보통 | 어려움 |
|---|---|---|---|
| 기본 방 문제 | `seed_variants.py` 의 쉬운 문제 (단서 2~3개, 한 단계) | `seed_data.py` 의 기본 문제 | `seed_variants.py` 의 어려운 문제 (함정 단서, 여러 단계) |
| 힌트 | 3개 (마지막은 거의 정답) | 2개 | 1개 (방향만) |
| 힌트 1회 감점 | 보통의 0.5배 | **제한 시간 30분마다 1분** (30분 → 1분, 60분 → 2분, 90분 → 3분, 120분 → 4분) | 보통의 1.5배 |
| 미니게임 | 한 단계 쉽게 | 기본 | 한 단계 어렵게 |
| AI 키가 있을 때 | 프롬프트에 난이도 기준을 넣어 **매번 새 문제** 생성 + 미니게임 난이도·힌트 수를 난이도 범위로 보정 | 〃 | 〃 |

- 예) 공포 1번 방: 쉬움 = 메모의 색상 숫자를 순서대로 → 3142 / 보통 = 숫자와 순서가 흩어진 단서 3개 → 3142 / 어려움 = 고장 난 LED 제외 + 역순 규정 → 2413
- 공포 4번 방은 어려움에서 자물쇠 암호가 추가되고, 이집트 2번 방은 어려움에서 다른 수수께끼가 나옵니다.
- 관리자가 고친 방·새로 만든 테마는 준비된 변형이 없으므로, 같은 문제에 힌트 수와 미니게임 난이도만 바뀝니다.
- 5분 단위 시간도 같은 비율입니다 (45분 → 1분 30초). 로비의 제한 시간 옆과 퍼즐 창의 힌트 칸에 이번 게임의 감점이 표시됩니다.
- `HINT_PENALTY_SEC` 를 바꾸면 세 난이도·모든 제한 시간의 감점이 같은 비율로 바뀝니다.

### 자동 검사 (CI · GitHub Actions)
푸시할 때마다 `.github/workflows/ci.yml` 이 실제 컴퓨터에서 실행됩니다.

| 작업 | 내용 |
|---|---|
| backend | 백엔드 테스트 — Ubuntu(Python 3.10·3.14), Windows, macOS (설치 파일(wheel)만으로 설치되는지 포함) |
| frontend | 타입 검사 + 빌드 |
| e2e | `start.sh` 로 서버 실행 → 브라우저 자동 테스트(붉은 서재·공포·파라오) → `stop.sh` 후 포트가 닫혔는지 확인 |
| launch | Windows `start.bat` / macOS `start.sh` 실행 → 응답 확인 → 다시 실행(이미 켜진 서버 건너뛰기) → 종료 확인 |
| ai-live | 저장소 **Settings → Secrets → Actions** 에 `GEMINI_API_KEY` 를 등록하면 실제 AI 로 방·힌트 생성까지 확인 (없으면 건너뜀) |

실제 AI 연결은 로컬에서도 확인할 수 있습니다: `cd backend && python -m scripts.ai_smoke` (`.env` 의 키 사용, AI 호출 3번)

## 3. 게임 규칙 (구현 완료)

| 항목 | 값 | 구현 위치 |
|---|---|---|
| 방 개수 | 기본 **4**, 최소 2 ~ 최대 5 | `config.py`, `game_logic.select_rooms` |
| 방 구성 | 입구(1번)·최종 방(5번)은 항상 포함, 중간 방을 순서대로 채움 | `select_rooms` |
| 제한 시간 | 30 ~ 120분, 사용자가 로비에서 선택 (5분 단위) | `Lobby.tsx`, `CreateSessionRequest` |
| 타이머 | 서버 기준 (`started_at + 제한 + 관리자 추가 시간`) | `game_logic.remaining_seconds` |
| 진행 | 방 클리어 → 다음 방 문 열림 → 최종 방 클리어 시 탈출 | `game_logic.submit_answer` |
| 퍼즐 창 | 왼쪽 **문제** 칸(지시문·모은 단서·답 입력)과 오른쪽 **힌트** 칸(테마별로 다른 색의 카드, 사용/전체 수, 감점 안내, 한 번 더 확인해야 시간 차감)을 분리 | `PuzzleModal.tsx` |
| 정답 판정 | 공백·대소문자 무시, `\|` 로 복수 정답 (`사람\|인간`) | `game_logic.check_answer` |
| 3D | 1인칭 (WASD, 마우스, Shift, E 조사), 잠긴 문 충돌, 벽 너머 조사 불가 | `engine.js` |
| 단서 | 조사 시 팀 인벤토리(I)에 공유, 조사 전에는 내용 비공개 | `game_logic.inspect_clue`, `ClueDoc.tsx`, `InventoryPanel.tsx` |
| 미니게임/열쇠 | 서버가 문제 생성·검증(1회용) → 열쇠 → 문에서 사용 | `minigames.py`, `components/minigames/`, `Game.tsx` (문 상호작용) |
| 지도 (M) | 방별 클리어 ✅ / 진행 가능 🔓 / 잠김 🔒, 내 위치·팀원 위치, 문 상태, 단서 수·암호·열쇠 상태 | `MiniMap.tsx` |
| 협동 | WebSocket: 위치 동기화, 채팅, 클리어/힌트/관리자 알림 | `ws_manager.py`, `socket.ts` |
| 관리자 | 인게임 🛠 버튼 → 컨셉·방·퍼즐·**단서(위치/모양/내용)·미니게임(종류/난이도/열쇠 이름)** 편집, AI 편집, 시간/잠금/초기화, 로그 | `AdminPanel.tsx`, `routers/admin.py` |

> 퍼즐은 **다른 방의 단서에 의존하지 않도록** 설계했습니다. 방 개수에 따라 중간 방이 빠지기 때문입니다.

## 5. API 요약

### 플레이어
| Method | Path | 설명 |
|---|---|---|
| GET | `/api/config` | 방 개수/시간 범위, AI 모드 |
| GET | `/api/themes` | 테마 목록 |

| POST | `/api/sessions/{id}/rooms/{slot}/answer` | `{answer, player_name}` |
| POST | `/api/sessions/{id}/rooms/{slot}/hint` | `{level}` → AI 힌트 |
| POST | `/api/sessions/{id}/rooms/{slot}/clues/{clue_id}/inspect` | 단서 조사 → 인벤토리 추가 |
| POST | `/api/sessions/{id}/rooms/{slot}/minigame/start` | 미니게임 문제 받기 |

## 6. AI 연동 (구성원 1)

- 현재 `AI_PROVIDER=mock`: 카이사르 암호·수열·수수께끼·색 코드 퍼즐을 규칙 기반으로 생성하며, **퍼즐 정보를 2~3개 단서로 나누고** 50% 확률(최종 방은 항상)로 미니게임을 붙입니다. 힌트는 DB 힌트 → "정답 N글자, ○로 시작" 순.
- 실제 LLM 은 `prompts/generate_room.txt` 의 JSON 형식(단서·미니게임 포함)으로 방을 만들고, 형식이 틀리면 mock 으로 대체됩니다.
- 실제 LLM 연결: `backend/.env` 에서 `AI_PROVIDER=claude` 또는 `gemini`, `AI_API_KEY=...` 입력 (Gemini 무료 키는 Google AI Studio 에서 발급).
- **게임마다 새 문제** (`AI_RANDOM_ROOMS=true`, 키가 있을 때 기본): 게임을 만들 때 방마다 AI 에게 동시에 요청해 이름·묘사·퍼즐·정답·힌트·단서·미니게임을 새로 만듭니다.
  - 방마다 다른 퍼즐 유형(암호·수열·수수께끼·코드·논리)을 지정해 겹치지 않게 하고, 단서는 가구와 겹치지 않는 자리에 다시 배치합니다.
  - 형식이 틀렸거나 정답이 없는 초안, 시간(`AI_TIMEOUT_SEC`) 안에 오지 않은 방은 버리고 **테마의 기본 방**으로 진행합니다.
  - 생성된 방은 그 게임(`session_rooms.room_json`)에만 저장되어, 관리자가 편집하는 테마의 기본 방은 바뀌지 않습니다.
  - 무료 키는 하루 요청 수가 적으므로 (방 4개 게임 = 요청 4번) 한도가 걱정되면 `AI_RANDOM_ROOMS=false`. 호출이 실패하면 자동으로 mock 으로 대체되어 게임은 멈추지 않습니다.
- **비용 보호**: 게임 생성은 누구나 호출할 수 있으므로, AI 호출이 무한정 늘지 않게 세 겹으로 막습니다. 넘으면 오류 대신 **기본 방 / 기본 힌트**로 진행하고, 게임 화면에 이유를 안내합니다.
  1. 하루 전체 한도 `AI_DAILY_LIMIT` — DB(`ai_usage`)에 기록해 서버를 다시 켜도 유지, 동시에 요청이 와도 한도를 넘지 않게 예약(조건부 갱신)
  2. 같은 IP 의 AI 게임 수 `AI_GAMES_PER_IP_HOUR` (프록시 뒤라면 `TRUST_PROXY=true`)
  3. 동시 생성 수 `AI_MAX_CONCURRENT_GAMES` — 생성 중인 게임이 가득 차면 새 게임은 기다리지 않고 기본 방
  - 로비에 "오늘 남은 AI 호출 N회"를 표시하고, 남은 수가 방 수보다 적으면 기본 방으로 진행된다고 미리 알려 줍니다.
- 다른 LLM 사용 시 `ai_service.py` 의 `AIProvider.complete()` 만 구현하면 됩니다.
- 프롬프트 수정은 `backend/app/prompts/*.txt` 에서 (코드 수정 불필요).
